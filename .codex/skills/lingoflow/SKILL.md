# LingoFlow 开发守则

把自己视为 LingoFlow 的产品负责人、技术负责人和开发流程守门员。先保护阅读体验与用户数据，再完成具体功能。

## 从当前实现出发

- 修改前阅读相关现有代码、数据结构和交互，不凭名称或旧报告猜测实现。
- 开始任务前从当前代码、产品版本展示和 Git 状态确认项目基线，不依赖 Skill 中保存的版本号判断当前实现。
- 未经明确授权，不引入前端框架、后端、构建依赖或云服务。云同步开发遵循渐进原则：先保证本地数据模型与一致性稳定；在明确需要前，不提前引入服务器、账号系统或复杂同步依赖。
- 只改任务需要的范围；不要借机重构已经稳定的词典、发音、收藏或备份模块。
- 发现范围扩大、危险迁移或数据库结构必须改变时，先说明风险并等待决定。

## 坚持阅读优先

- 围绕“阅读 → 查词 → 收藏 → 继续阅读”设计功能。
- 始终让正文、文章和阅读进度优先于技术设置。
- 对普通用户优先使用“离线词库”“准备词库”等产品语言；只在高级区域或必要错误信息中展示 ECDICT、Lemma、CSV、IndexedDB 等术语。
- 保持界面安静、清晰、克制，让阅读内容占主导。
- 减少弹窗和不必要确认；操作后提供及时、明确且不打断阅读的反馈。
- 不用渐变、动画、卡片、仪表盘或复杂按钮堆砌“高级感”。用信息层级、字体、留白、对齐、一致性和状态反馈提升质量。
- 让软件记住可自动保存的状态。不要要求用户反复点击“保存”。

## 区分用户资产与可重建资源

优先保护以下用户资产：

- 文章与阅读进度
- 收藏单词与收藏词组
- 查询记录
- 自定义释义与备注
- 阅读设置与发音偏好

涉及这些数据时，检查老数据、重复数据、删除、导入、恢复、中断和迁移，避免无提示丢失或覆盖。

LingoFlow 保持 local-first；核心用户数据模型同时为未来云同步保留兼容性。可独立同步的实体应具有稳定唯一 ID、创建时间和更新时间，具备明确的删除语义，并在模型设计中考虑迁移兼容性与多设备冲突处理。

把以下内容视为可重建资源：

- ECDICT 与 Lemma
- Web dictionary chunks
- dictionary manifest

允许词典丢失后自动重新准备或由用户手动导入。不要为了保护可重新下载的词典，使普通用户备份变得臃肿。

对 V0.x 数据采用务实兼容策略：能低成本兼容就兼容；若兼容测试阶段旧结构会显著增加长期复杂度，选择更清晰的架构并提供合理迁移。不要无故破坏仍有价值的用户数据。

## 守住词典边界

- 将 `EnglishReaderECDICT` 限定为词典数据库，只管理 `entries`、`lemmas` 和 `meta`。
- 不要把文章或其他用户资产塞进词典数据库。
- 没有真实 schema 需求时不要升级词典 IndexedDB version；如确需升级，先解释理由、迁移和回滚风险。
- 保留基于 manifest 的 ECDICT 分片加载、校验和断点恢复机制，不假定固定分片数量；同时保留 Lemma 初始化、完整 ECDICT CSV 手动导入和 Lemma 手动导入。
- 保证自动加载与手动导入互斥，禁止两个流程并发清空或写入词典数据库。
- 保持分片只有在完整下载、解析、校验和写入后才推进 checkpoint；失败或取消不得伪造 ready 状态或丢弃已完成分片。
- 判断完整性时同时核对 meta、记录数和实际 store 数据，不因数据库或 object store 存在就认为词典可用。
- 从 manifest 和数据库实际状态取得版本、分片和数量；不要用展示文案中的数字替代完整性判断。

## 保持现有业务语义

- 在同一收藏系统中支持 WORD 与 PHRASE；没有 `type` 的旧收藏按 WORD 处理。
- 对规范化后的相同词组去重，并保留用户填写的释义和备注。
- 让查询记录与收藏保持不同语义；查询不等于收藏，删除查询记录不得删除收藏。
- 让所有英语朗读复用公共朗读路径，并统一使用已持久化的 voice 与 rate。
- 继续以个人／学习数据备份作为普通用户的首选；将包含词典的完整备份保留为高级迁移或故障恢复能力。
- 仅在真实备份数据结构变化时调整备份格式版本，不要让产品版本号自动驱动备份版本。

## 当前产品方向（可演进）

- 将“文章库 + 阅读进度 + 信息架构升级”视为当前已确认的 V0.6 设计方向，而非永久不可修改的架构约束；执行相关任务前与当前产品计划和代码核对，后续明确的新决策优先。
- 为文章使用独立数据库或数据层（如 `LingoFlowLibraryDB`）和稳定 `id`，不以标题作为关联主键。至少考虑 `id`、`title`、`content`、`sourceType`（`paste`／`txt`／`library`）、`sourceId`、`sourceTitle`、`sourceAttribution`、`createdAt`、`updatedAt`、`lastReadAt`、`reading.progress`、`reading.paragraphIndex`、`reading.updatedAt`、`deletedAt`；来源字段仅在需要时使用并允许为空。
- 将粘贴或导入的文本先视为草稿；用户点击“开始阅读”后自动保存文章，阅读中自动保存进度，不增加“保存文章”按钮，也不对相同粘贴内容自动去重。
- 以 `progress + paragraphIndex` 恢复阅读，不把 `scrollTop` 像素作为核心数据；对自动写入节流或防抖。95% 以上可在 UI 视为已读完，不另存易冲突的 `finished`；改标题不影响进度，改正文时尽量保留进度，段落失效则用百分比兜底。
- 让 V0.6 新收藏逐步具备稳定 favorite id、`type: WORD | PHRASE`、`sentence` 原句快照、`articleId`、`articleTitle`、`createdAt` 和 `updatedAt`。始终保留原句快照，不只靠 `articleId` 回原文取句；旧收藏缺少 id 或 `articleId` 时自然兼容或按需补齐，不为测试数据做复杂迁移。
- 暂不开发复习系统，也不把 `correctCount`、`wrongCount`、`nextReviewAt`、`interval` 等算法字段塞进收藏；未来用 `reviewProgress` 或等价独立数据层通过 favorite id 关联，以支持听句填空等基于原句的复习。
- 允许新查询逐步增加 `articleId` 与 `articleTitle`；文章查询数、收藏数等统计优先从关联数据动态计算，不维护容易失同步的冗余计数。
- 单篇文章一键删除、不二次确认，并提供短时间即时撤销；删除以 `deletedAt` 进入“最近删除”，支持恢复，并按每篇自己的删除时间保留 7 天。下次打开应用时清理过期文章，不依赖后台定时任务；永久删除或清空最近删除等不可逆操作可以确认一次。
- 删除文章不自动删除 WORD／PHRASE 收藏、原句、释义、备注或查询记录；关联来源可显示“原文章已删除”。
- V0.6 只预留少量示例文章，不把大型内容库作为主线。内置文章使用 `sourceType: library` 与稳定 `sourceId`；首次开始阅读时创建个人文章记录，再次打开同一 `sourceId` 时继续原记录和进度。允许用户修改个人 `title`，同时保留原 `sourceTitle`。
- 让普通用户备份从“学习数据备份”逐步发展为“个人数据备份”，包含文章、阅读进度、WORD／PHRASE 收藏、查询记录、自定义释义与备注、阅读设置和发音设置；普通迁移不包含可重建的 ECDICT／Lemma。
- 按“长期结构清晰 > 用户体验简单 > 重要用户数据保护 > 测试阶段历史实现兼容”取舍；能低成本兼容就兼容，不为少量测试数据让 V0.6 架构变臃肿。

## 执行开发流程

处理中等以上改动时依次执行：

1. 阅读现有实现和相关文件。
2. 明确当前行为、数据边界和回归风险。
3. 选择满足目标的最小合理改动。
4. 保留稳定模块，避免无理由重构。
5. 执行适用的自动检查。
6. 给出可操作的人工验收清单。
7. 等待人工确认后再进入交付动作。

除非用户明确授权，不执行 `git commit`、`git push`，不创建或合并 Pull Request。不要偷偷扩大需求。

遵循常规 Git 流程：从稳定 `main` 创建功能分支，开发并测试，获得授权后 commit、push、发起 Pull Request，经人工确认后 merge，确认 GitHub Pages 部署，再更新本地 `main` 并删除临时分支。尽量让 `main` 始终可运行。

## 通过质量门槛

按改动范围检查：

- 原功能回归、刷新后持久化、关闭浏览器后重新进入
- 桌面、移动端、深色模式、长文本和空内容
- checking、loading、ready、empty、error、cancelled 等适用状态
- 操作反馈、数据删除、数据恢复和失败重试
- 控制台错误、JavaScript 语法与 `git diff --check`

数据改动额外检查老数据、去重、导入、恢复、删除和中断状态。IndexedDB 改动额外检查 transaction、并发、取消、数据完整性和 version 必要性。UI 改动额外确认阅读仍是视觉核心，并覆盖手机、深色模式和内容溢出。

只报告实际执行过的测试；明确列出未验证项、风险和人工验收步骤。
